## 实际流程

1. 本人登录后打开“永久注销”，说明会删除资料、本人正文、相关关系，相关举报只去掉本人身份后保留；他人原消息、共享课程和必要非识别占位保留。它不同于退出、个人清空、屏蔽或封号。
2. 调用 challenge，向 Auth 服务器确认当前账号，再向其当前邮箱发六位验证码，`shouldCreateUser=false`。邮箱和 userId 均由服务端推导，不接受客户端输入。无需先补资料或恢复开放学校；托管邮件／Hook 的真实行为仍须联调。
3. **先持久保存随机 receiptToken**，再提交验证码、challengeToken 和明确的 DELETE 确认。页面的确认弹窗不能代替这些服务端检查。
4. 服务端检查签名、十分钟有效期、当前 Auth 身份、回执绑定及验证码验证出的身份一致；只将可信 userId 与回执摘要传给 service_role 专用 RPC。验证码创建的临时会话不返回给 App，失败时尽力撤销，成功时随账号删除。
5. 数据库在同一事务中清理相关证据、本人内容和身份、关系／订阅、Auth 主记录及可识别审计字段，最后记录不含账号身份的完成回执。任何 SQL／外键／Auth 删除错误均回滚。
6. 返回 completed 后清本人凭据、缓存、草稿、失败发送项与该设备关联；原生端具体实现由前端负责人完成。网络中断或 503 时只锁定并保留查询回执，不得假报成功。

## HTTP 契约

基础路径 `/api/mobile/v1`；三个入口都是 POST、application/json，最多 16 KiB，无查询参数或未知字段。响应 private/no-store、不设置 Cookie，错误方法为 JSON 405。不要把验证码、签名确认或回执放进 URL／日志／普通分析事件。

### POST /account/deletion/challenge

要求 Bearer，Cookie 不能冒充身份；请求 `{}`。该入口向 Auth 重新核对账号，独立于普通应用的学校／onboarding 准入，不能用它访问其他业务数据。

```json
{
  "status": "code_sent",
  "challengeToken": "<服务端签名确认，含本人及回执绑定>",
  "receiptToken": "<43字符随机凭据>",
  "expiresAt": 1790000000
}
```

示例为虚构占位；expiresAt 是 Unix 秒。签名确认不是加密数据，包含本人账号与邮箱，只作为短期敏感凭据保存，不作为可公开回执。验证码过期／被消费时需重新发码；限流沿用 Supabase 实际响应，不提供虚构重发倒计时或 Retry-After。

### POST /account/deletion

要求 Bearer；全部四个字段必填：

```json
{
  "challengeToken": "<challenge返回值>",
  "receiptToken": "<challenge返回值>",
  "code": "123456",
  "confirmation": "DELETE"
}
```

成功 `{"status":"completed"}`。重复提交已完成的随机回执只返回 completed，不再次删除；它不能改成指向另一个账号或同邮箱后来注册的新身份。不能提交 userId、email、举报处理选项、任意 RPC 名称或附件。

### POST /account/deletion/status

请求 `{"receiptToken":"<原随机回执>"}`。这个入口**只消费随机凭据，不消费 Bearer 或 Cookie**，因此已删除账号或已过期登录仍能查询。返回只含 `status=completed` 或 `not_completed`，不提供账号、邮箱、正文或举报详情。

not_completed 表示“尚未确认完成”，可能是未执行、已回滚或原请求仍在事务中，**不证明已经失败**。保留回执并退避重查；若需重新发码，不能丢弃原未决回执。所有未决回执必须查询确认，不能把一次新 challenge 的回执当作旧请求的结果。SQL 结果未知时避免自动连发删除请求。

完成回执库只保存随机凭据的 SHA-256 摘要和完成时间，没有 userId、邮箱、正文或账号外键；未完成事务不会留下 completed 记录。App 确认成功后删除本地回执和签名确认。旧回执不能作为新账号身份凭据，也不能恢复被删除数据。当前没有自动清理这类无身份完成元信息的调度，不将其误称为举报保留期限。

## 状态与失败处理

| HTTP／status | 前端处理 |
|---|---|
| 200 code_sent | 提示收取当前邮箱验证码，先存回执再继续；不要显示任何新登录凭据 |
| 200 completed | 清本人本机数据／凭据，回未登录页，结束设备关联；不只“保留但锁定” |
| 200 not_completed | 只用于回执查询；继续确认原请求，不假报成功或立即认定回滚 |
| 400 invalid_request | 字段、DELETE 确认、六位字符串验证码、回执格式或查询参数错误 |
| 400 invalid_challenge | 签名、有效期或回执绑定不符；需重发，保留原未决回执 |
| 400 invalid_or_expired_code | 验证码不正确／已过期；保留意图并允许用户重新核验 |
| 401 authentication_required／access_token_invalid | 发码／执行需本人有效登录；先查原回执，再按认证流程处理，不能冒认删除完成 |
| 403 identity_mismatch | 当前登录、签名确认和验码身份不一致，停止操作，不能替换成另一目标 |
| 409 owner_transfer_required | 沿用唯一 owner 保护，先按现有管理手册完成所有权转交；无数据已删，不暗中增加转让权限 |
| 409 storage_cleanup_required | 部署库有本人 Storage 对象，本版没有上传／对象清理链，未执行任何删除；必须先纳入受控清理，不建议用户自行乱删存储 |
| 404 not_available | 原账号已不存在且该回执未确认完成；不能拿同邮箱的新账号替代目标 |
| 429 rate_limited | 按真实供应商限流反馈稍后重试，不虚构准确等待时间 |
| 503 temporarily_unavailable | 配置缺失、供应商／SQL 故障或未知结果；先查原回执，绝不显示为已完成 |

413／415 沿用统一请求边界。校验失败不开始删除；SQL 失败整体回滚。邮件发出不表示删除已发生，验证码验证成功也不等于已删除。删除失败时临时验码会话撤销为尽力操作，网络故障不能保证额外会话撤销已完成；该凭据从不返回 App。

## 实际数据与权限影响

- 新迁移 `202610260001_permanent_account_deletion.sql`；新表 account_deletion_receipts 对所有 API 角色无直接权限；新删除／查询 RPC 仅 service_role 可调用。普通成员不能任意删除账号或访问证据。
- 关联举报匿名保留，覆盖本人作为举报人、被举报人、本人消息及相关申请的材料：`behavior_reports.reporter_id` 与 `report_evidence.reported_user_id` 改为可空并置空；证据快照去掉 `profile_id`／`display_name`／`avatar_url`／`major`／`grad_year`，加 `"subject": "deleted_account"`；资料举报的多态 `target_id` 与留存 `source_id` 改为 `deleted:<report_id>`。消息／申请正文快照保留，所以被举报人注销不能抹掉别人对他的举报，举报人注销也不撤回已交的举报。无关举报不变，别人原始消息不删除。审核端读到空 ID 应显示“已注销账号”。
- 不可变触发器只允许受控 definer 注销函数在明确事务上下文内释放相关材料。单独设置同名参数不授予权限；普通证据不可变规则仍然有效。
- 举报创建和注销共用事务锁，防止账号注销后又写回旧证据；当前会短暂串行化举报／注销。其他消息仍通过既有受控 RPC，成员行锁与外键约束处理注销期间的关联写入。真实多连接竞争仍待验证。
- 本人消息统一变成 sender_id=null、固定非内容占位、deleted_at 非空、client_message_id/source_friend_request_id=null。消息 ID／会话保留，普通读取排除该行，reconcile 返回旧 ID 不可见。其他成员正文和当前读取不受影响。
- 清理涉及本人的好友申请及无账号外键的配对 UUID；剩余成员的会话和原消息保留，申请引用通过既有 SET NULL 断开。
- 删除 Auth 主记录并依赖身份／会话真实级联，另处理旧版文本 user_id 的 refresh_tokens。明确的 Auth 审计 actor／traits 身份和邮箱、平台审计的本人 target／email 字段定向清理。托管 schema 的真实版本必须在部署前核对。
- 本人成员、资料、选课／会话成员、关系／偏好／拉黑、计数桶、管理上下文及网页推送订阅随账号级联。共享课程与会话保留，创建者置空。网页推送事件去重元信息只引用消息／申请事件，不含订阅密钥和账号绑定，不能作为正文恢复来源。
- 删除后旧 JWT 的签名仍可能有效，现有 get_member_context／RLS 因成员消失拒绝业务访问；刷新凭据随 Auth 删除失效。回执查询是独立的最小凭据入口，不能访问普通业务。

使用数据库内事务而非先清业务再另发 Auth 删除 HTTP，目的是消除跨请求部分完成；没有修改 Supabase 管理 API 或全局会话策略。真实 Auth 内部表、外部日志／备份、其他托管对象的清理仍是部署核对项，不能以本地简化 fixture 声称全部覆盖。

## 原生及网页缓存要求

本人明确确认后立即锁定该账号敏感页面和写队列，阻止返回／通知继续打开；先保留最小回执用于恢复。completed 才清本人数据库分区、凭据、草稿、失败发送、举报内容／回执、导航目标及设备绑定。普通退出仍保留但锁定，不改成永久删除。

其他已登录客户端恢复联网时按 [消息恢复协议](mobile-messages-api.md) 校验身份、全部已缓存 ID 与覆盖范围，移除已不可见正文和旧发送失败项；序列代次防止旧请求把正文写回。旧身份重新登录失败时锁定／清理按实际确认结果处理，不能恢复到同邮箱的新账号。本版没有实现原生本机库或网页已打开内存窗口的删除事件处理；这些前端配合必须联合验收，不能只依据 HTTP 成功宣布受控副本全部清除。

不承诺即时抹除离线设备、已经投递的系统通知、他人独立截图／导出或平台备份。实际备份、Auth 外部日志、分析渠道和运营导出的范围／期限需要部署负责人核实并更新隐私说明；默认删除数据库当前记录不等于这些副本全部清除。

## 配置、迁移与验收

服务端需要 SUPABASE_SERVICE_ROLE_KEY 和至少 32 字符的 EMAIL_OTP_CONTEXT_SECRET；注销独立于 VAPID 是否配置。两种管理用途使用隔离客户端，不向 App、日志或 Notion 暴露管理密钥。旧环境不配置管理密钥时本功能返回 503，不改变原登录／课程／好友／消息接口。

2026-10-27 只读核对生产库（CourseMate-east）：`postgres` 对 `auth.users`／`auth.sessions`／`auth.refresh_tokens`／`auth.audit_log_entries`／`storage.objects` 均有 DELETE 权限，且没有引用 `auth.users` 的 RESTRICT／NO ACTION 外键；权限层面不会挡住注销事务。真实删除一个测试账号仍待执行。
