## 效果与证据

- **「服务」读数**（延迟显示，用户单机读数）：搬迁后约 255ms（偶发 300–1200ms）→ #35 之后平均约 170ms（最低 135、最高 400）。#37 之后的读数没有记录。
- **课程页一次加载在 Supabase 侧的调用**（新项目 `edge_logs`，单次抽样）：迁移当天旧代码（01:41）从第一个校验调用到最后一个数据查询约 **1.4s**，几乎全是串行：校验三次调用重复多轮，数据阶段 9 步串行；今天（04:19）约 **0.21s**：校验只剩两次 `get_member_context`（proxy 与页面各一次），**没有 `/auth/v1/user`**；课程、成员身份、会话关联三个查询在同一个 4ms 内发出，名单、最近消息、好友关系摘要在同一毫秒发出。注意这是单次抽样，且期间还叠加了 `cle1`、函数冷热等因素，只能说明量级。
- **本地验签**：部署后 `get_member_context` 155 次全部 200（Supabase 侧处理中位数约 29ms）；`/auth/v1/user` 0 次；`jwks.json` 拉取 8 次（每个新函数实例首次一次）。
- **令牌有效期**：日志里的令牌 `issued_at` / `expires_at` 显示，重新登录后签发的令牌是 900 秒，此前签发的还是 3600 秒，说明后台设置已生效。
- 部署后没有 4xx，唯一一次 `409` 是资料保存"先 insert、唯一键冲突再 update"的预期行为。

## 关键取舍

- **本地验签换来"别处退出登录最长 15 分钟才失效"**，已用缩短令牌有效期缓解，详见 [ADR-0009](../adr/0009-verify-access-token-locally.md)。后台删除用户仍立即生效（每次读成员账号）。
- **私聊页行为变化**：会话没授权时，原来不去取消息，现在两个请求同时发出。两个接口各自由数据库授权，页面只在两者都成功时才渲染，否则 404。
- **没有改的**：好友页本来就是并行取数；发课程消息直接调用数据库函数，不经过会话解析；`getJoinedCourse` 只在退出课程时用，改了收益太小，已撤销。
- proxy 在边缘节点运行，不受 `vercel.json` 的 `regions` 约束：`cle1` 上线后 proxy 里约 87% 的 Supabase 调用仍来自 us-east-1（用日志里的调用方 IP 对照 AWS 地址段得出，属推断）。所以减少调用次数比换区域有效。

## 给接手者的提示

- **迁移先于前端**：新增数据库函数的迁移必须先在生产应用，再发布依赖它的前端。函数不存在时 proxy 会把所有请求当作未登录。
- **对预览点 Promote 是重新构建那个预览的提交**，不含之后合并的改动；要发 `main` 的当前状态用 `npx vercel deploy --prod`（先确认本地是干净、最新的 `main`）。
- **Claude 会话里对生产库的写操作**（授权、迁移历史登记、`supabase_migrations` 补行）会被权限分类器拦下，由所有者在 SQL Editor 执行；只读核对（MCP 的 `execute_sql`、`query_logs`）不受影响。
- 后台设置不随 dump 迁移，搬迁或新建项目时逐项重配，包含 **Access token expiry time = 900**。
