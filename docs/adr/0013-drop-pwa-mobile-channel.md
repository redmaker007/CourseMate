# 放弃 PWA，手机端只做原生 App

2026-11-22 团队决定：不再把 PWA（网页「添加到主屏幕」）当作手机端渠道。手机端只做 React Native + Expo 原生 App（先做 iOS，见[适配约定评审](../handoffs/app-adaptation-review.md)）；网页只是浏览器里的网站，不再为「装到手机上用」做额外工作。

这条改写了此前的路线：「PWA 保留为网页与 Android 的渠道」（STATUS 2026-10-04 起的下一步第 4 条）。

## 为什么

试用效果团队不满意。PR #55、#56 做过的 PWA 部分（清单、图标、安全区、Service Worker 和离线页、「安装到手机」卡片）在 2026-10-04 上线，但真机验收一直没走完，也没换正式图标。

## 影响

- **不再做**：PWA 真机验收、正式 PWA 图标、「添加到主屏幕」的体验打磨。Android 也不再靠 PWA 覆盖，等原生 App 再说。
- **网页推送随之降级**：iPhone 只有「添加到主屏幕」的网页才能收到网页推送。放弃 PWA 后，网页推送（PR #57，生产仍关闭）对手机用户基本没用，只剩电脑浏览器能收到。手机通知改由原生 App 的 APNs 推送负责（后端已随 PR #58 上线，配置待补）。要不要还为电脑浏览器启用网页推送，另行决定。
- **现有代码暂时保留**：manifest、Service Worker、离线页、`viewport-fit=cover` 和安全区样式、「我的」页的「安装到手机」卡片仍在 `main` 和生产上，没有删除。安全区和移动端布局对手机浏览器访问网页仍然有用；只对 PWA 有意义的部分（安装卡片、离线页、Service Worker）要不要移除，另行决定。删除 Service Worker 时要发一个注销旧 worker 的版本，否则已安装的用户设备上会残留旧 worker。

## 何时重新审视

原生 App 迟迟上不了架，或者 Android 用户需求明显、但又没有能力维护 Android 原生版本时。届时写新的 ADR 取代本篇。
