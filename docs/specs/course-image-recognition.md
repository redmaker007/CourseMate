# 选课页面图片识别与批量加课规范

状态：部分实现（Issue #50），Issue #51–#54 待实现
日期：2026-09-29

## 背景

成员目前需要逐门搜索并加入课程。CourseMate 需要允许已登录成员上传学校选课页面的截图，从中识别课程，在当前学校、当前学期的课程中生成候选，并由成员确认后一次加入。

图片识别只负责生成候选，不能替成员作出选课决定。数据库仍是课程存在性、学校归属、当前学期、成员权限和最终写入结果的权威来源。

## 已确认决策

- 第一版只识别选课页面中有哪些课程，不理解课表时间、星期、地点或冲突。
- 使用 Google Cloud Vision 做服务端 OCR；不通过轮换 Google 账号或项目规避费用和额度。
- 图片只在当前请求中处理，不写入 Supabase Storage、数据库或日志。
- 课程匹配以课程代码为第一优先级，课程名称只作辅助和兜底。
- OCR 提取图片中出现的全部课程代码，再按主课程、引用课程或上下文不确定分类；课程名称不是生成代码候选的必要条件。
- 页面用带背景遮罩的模态框展示候选；关闭模态框立即丢弃结果，不保存识别会话。
- 成员主动勾选后才能加课；识别本身不得自动写入课程成员关系。
- 批量加课必须原子执行：全部成功或全部不写入。
- 已加入的课程继续显示为“已加入”，但不能再次勾选。
- HEIC 由客户端自动转换为标准图片格式；用户不需要手动转换。
- 全站每月最多发起约 7,000 次 OCR 请求；每位成员任意 10 分钟内最多 5 次。
- 失败提示区分课程状态、登录权限和临时服务错误，不把所有失败伪装成网络问题。

## 目标

- 从一张选课页面截图中识别零门或多门课程。
- 只返回当前成员所属学校、当前学期的可加入课程候选。
- 让成员清楚区分高可信代码匹配、名称匹配和已经加入的课程。
- 在并发或课程状态变化时保持批量加课的数据一致性。
- 把单月 OCR 成本控制在约 10 美元以内，并避免单个成员快速耗尽全站额度。
- 为未来替换 OCR 服务保留清晰模块边界，但不提前构建多供应商框架。

## 非目标

- 不识别上课时间、星期、地点、教师、section 或课程冲突。
- 不解析 PDF、手写课表、拍照文档集合或多页文件。
- 不引入 RAG、向量数据库、embedding、Agent 或语义搜索。
- 不集成或部署完整的 PaddleOCR / PP-StructureV3；第一版只借鉴其“预处理、保留文本块顺序、结构化后再匹配”的处理思路。
- 不保存图片、OCR 原文、候选结果或未确认的勾选状态。
- 不在本功能中决定 Capacitor、Expo/React Native 或 SwiftUI 等 App Store 封装技术。
- 不支持多个 Google 账号或项目轮换免费额度。

## 用户流程

1. 已登录并完成 onboarding 的成员在主页面选择一张选课页面图片。
2. 客户端检查文件类型；HEIC/HEIF 自动转为 JPEG，其他支持格式按需压缩。
3. 客户端只上传处理后的 JPEG、PNG 或 WebP。
4. 服务端重新验证身份、真实文件类型、文件大小和像素边界。
5. 服务端原子检查并消耗个人短期限额和全站月度额度。
6. 服务端把图片发送给 Google Cloud Vision，并立即释放请求内图片数据。
7. 服务端整理 OCR 文本块，提取可能的课程代码和名称。
8. 服务端结合文本块位置和附近文字，把代码出现位置分类为主课程、引用课程或上下文不确定，再只在成员当前学校、当前学期的 `courses` 中匹配候选。
9. 主页面变暗并打开模态框，展示候选、可信度、默认勾选和已加入状态。
10. 成员修改勾选并点击“一键加入”。
11. 数据库在一个事务中重新校验并写入全部选择；任一无效课程使整个操作回滚。
12. 成功后关闭模态框并刷新成员课程；关闭或取消时直接丢弃候选。

## 图片输入与转换

### 客户端

- 可选择 JPEG、PNG、WebP、HEIC 和 HEIF。
- HEIC/HEIF 必须在上传前自动转换为 JPEG。
- 转换与压缩不得要求成员离开 CourseMate 或使用第三方工具。
- 转换代码按需加载；选择普通格式时不加载 HEIC 转换逻辑。
- 输出图片目标不超过 3 MB，并优先保留文字可读性；不得为了尺寸目标把课程文字压缩到不可识别。
- 转换失败时不上传，提示成员更换图片或重新截图。

### 服务端

- 只接受单张 JPEG、PNG 或 WebP，拒绝客户端声称的类型与文件签名不一致的内容。
- 拒绝超过 3 MB、无法解码、像素异常或不是图片的输入。
- 不接受客户端直接上传的 HEIC/HEIF，也不在服务端安装 HEIC 转换链。
- 不以 Base64 JSON 接收图片，避免额外体积；使用 `multipart/form-data`。
- 图片仅存在于单次请求内存中，不落盘、不进对象存储、不进入错误日志。

## OCR 与结构化

- 第一版调用 Google Cloud Vision 的文档文本识别能力，读取文本、文本块顺序及可用的位置/置信信息。
- Google 凭据只存在于服务端环境变量；不得发送到浏览器或写入仓库。
- 对外只返回 CourseMate 的候选结构，不返回供应商原始响应。
- 结构化过程必须先提取所有类似课程代码的文本，再关联同一行、相邻文本块和可用的课程名称。
- 使用文本块顺序、重复课程行版式和附近的确定性关键词做简单上下文分类，不调用第二个生成式模型。
- `primary` 表示代码位于选中课程的主列表行；`reference` 表示代码位于前置要求、推荐课程或说明文字；`uncertain` 表示可以确认课程代码，但上下文不足以判断用途。
- 第一版至少识别 `prerequisite`、`pre-req`、`requires`、`recommended` 等引用上下文；关键词表必须可由真实截图测试扩充。
- 只做确定性的清理和规则匹配；不让生成式模型猜测不存在的课程。
- OCR 失败、无文字和有文字但无课程候选是三种不同结果。

## 课程匹配规则

匹配范围必须先限制为：

- `school_id` 等于成员当前学校；
- `term` 等于学校当前学期；
- 数据来自带学期的 `courses`，而不是直接把无学期的 `course_catalog` 当作可加入课程。

匹配顺序：

1. 所有课程代码出现位置都先完成标准化和数据库匹配，课程名称不是必要条件。
2. `primary` 代码完全匹配：高可信，默认勾选；附近名称只作佐证。
3. `reference` 代码即使匹配数据库也不生成候选。
4. `uncertain` 代码完全匹配：中可信，展示但不默认勾选，并标记“可能的课程”。
5. 没有可匹配代码时，标准化名称完全一致且只对应一门课程：中可信，展示但不默认勾选。
6. 同名课程对应多条记录时不擅自选择。
7. 第一版不使用编辑距离、模糊名称阈值或 embedding 自动决定候选。

课程名称标准化只处理首尾空格、连续空格和大小写。相同课程只返回一次，代码匹配必须覆盖同一课程较弱的名称匹配。

候选最少包含：

| 字段 | 含义 |
|---|---|
| `courseId` | 当前学期课程 ID |
| `code` | 数据库中的课程代码 |
| `title` | 数据库中的课程名称 |
| `matchedBy` | `code` 或 `title` |
| `context` | 代码候选为 `primary` 或 `uncertain`；名称候选为空 |
| `confidence` | `high` 或 `medium` |
| `defaultSelected` | 是否默认勾选 |
| `alreadyJoined` | 当前成员是否已经加入 |

## 模态框行为

- 打开时使主页面形成视觉遮罩，但不得破坏主页面状态。
- 使用可访问的 dialog 语义，打开后移动焦点，关闭后把焦点还给触发按钮。
- 支持明确的关闭按钮；关闭、取消或刷新页面都会丢弃结果。
- 高可信且未加入的课程默认勾选；名称兜底候选默认不勾选。
- 上下文不确定的代码候选显示“可能的课程”且默认不勾选；引用课程不显示。
- 已加入课程显示“已加入”并禁用复选框。
- 没有候选时说明“没有匹配到当前学校本学期的课程”，允许重新选择图片。
- 一键加入按钮只提交成员当前实际勾选且尚未加入的课程 ID。

## 额度与成本边界

### 个人限额

- 同一成员任意连续 10 分钟最多消耗 5 次识别额度。
- 未登录或未完成 onboarding 的请求不得调用 OCR。

### 全站限额

- 全站每个计费月最多消耗 7,000 次识别额度。
- 同时在 Google Cloud 配置 10 美元预算告警；预算告警不替代应用自己的额度检查。
- 7,000 次是按当前 Google Vision 定价预留余量后的运营值，不是永久价格保证；供应商价格变化时需重新核算。

### 计数语义

- 文件校验失败和客户端转换失败不计数。
- 服务端完成校验、准备向 Google 发出请求时原子消耗一次额度。
- 每次真实供应商重试都视为一次新调用并再次消耗额度。
- 多个并发请求不得越过个人或全站上限。
- 达到个人限额时返回可重试时间；达到全站限额时说明本月识别额度已用完。

## 原子批量加课

批量加入必须复用现有课程成员关系和课程会话创建规则，但不能在应用层循环调用单门加课。

数据库事务必须重新验证：

- 调用者已登录并完成 onboarding；
- 每个课程 ID 都存在、属于调用者当前学校和当前学期；
- 输入课程 ID 已去重；
- 已加入课程按成功的幂等结果处理；
- 任何不存在、跨校、过期学期或无权限课程都会使整个批次回滚；
- 成功写入继续触发现有的课程会话惰性创建和成员同步逻辑。

客户端显示的勾选状态不能替代数据库权限检查。批量函数不得接受客户端传入的 `user_id`、`school_id` 或 `term` 作为信任依据。

## 失败分类

| 类型 | 用户提示 | 是否适合重试 |
|---|---|---|
| 图片无效或转换失败 | 无法读取这张图片，请更换图片或重新截图 | 更换图片后 |
| 没识别到文字 | 图片中没有识别到清晰文字 | 更换图片后 |
| 没有课程候选 | 没有匹配到当前学校本学期的课程 | 可以 |
| 个人额度耗尽 | 操作过于频繁，请在显示的时间后重试 | 到期后 |
| 全站额度耗尽 | 本月课程识别额度已用完 | 下个额度周期 |
| 课程状态变化 | 部分课程当前无法加入，请重新识别或刷新 | 刷新后 |
| 登录或权限失效 | 登录状态已失效，请重新登录 | 重新登录后 |
| OCR、网络或临时服务异常 | 服务暂时不可用，请稍后重试 | 可以 |

浏览器不得展示 Google、Supabase、SQL、堆栈或内部权限函数的原始错误。

## 响应时间目标

- 标准图片从提交到候选返回的正常目标为 3–5 秒，不作绝对延迟保证。
- 等待达到 8 秒时，模态框继续保留并提示“识别时间比平时更长”。
- 等待达到 12 秒时结束本次等待，显示可重试的临时服务错误，不允许界面无限加载。
- 超时后的每次实际 OCR 重试都重新消耗一次识别额度。
- 性能验收必须记录多次运行的中位数和 P95，并区分客户端转换、上传、OCR 与匹配耗时。

## 安全与隐私不变量

- 上传、识别和批量加入均要求 authenticated 成员并完成 onboarding。
- 学校和学期从服务端会话与数据库读取，不信任客户端参数。
- 在调用供应商前验证文件签名、大小和可解码性，限制像素以防止异常图片消耗资源。
- OCR 凭据仅在服务端使用；日志不得包含凭据、图片字节、完整 OCR 原文或用户课程截图。
- 识别结果只存在于当前页面内存；关闭模态框或刷新后不可恢复。
- 数据库是额度并发控制和批量加课权限的最终边界。

## 接口边界

第一版保持最少接口：

- 一个 authenticated 图片识别 POST Route Handler，接收单张图片并返回候选。
- 一个 authenticated 数据库批量加课函数，接收课程 ID 数组并返回统一成功结果。
- 一个服务端 Google Vision 调用模块；只有出现第二个真实供应商时再抽象通用 provider 接口或路由器。

不得为未来可能存在的多供应商、永久识别会话、后台任务或向量检索预先搭建框架。

## 验收标准

- 一张包含多门课程的有效截图能产生当前学校、当前学期的去重候选。
- `CS 540`、`cs540` 和 `CS-540` 能匹配同一课程代码。
- 主课程 A 的说明中出现前置课程 B 和条件课程 C 时，A 是默认勾选候选，明确位于前置/说明上下文的 B、C 不成为候选。
- 缺少课程名称不会阻止代码候选生成；无法判断上下文的有效代码显示为未勾选的“可能的课程”。
- 其他学校或其他学期的同代码课程不会成为候选。
- 只有名称唯一、完全标准化匹配时才产生名称候选，且不默认勾选。
- HEIC 对成员表现为自动处理，服务端最终只收到标准格式。
- 关闭模态框或刷新页面后识别结果消失，服务端没有保存图片或结果。
- 已加入课程可见但不可勾选；并发重复加入保持幂等。
- 批量加入中任意课程失效时没有任何新增课程成员关系。
- 个人和全站并发请求不能突破各自额度。
- 错误按既定类别提示，内部供应商和数据库错误不泄露。
- 正常识别以 3–5 秒为目标；8 秒出现慢速提示，12 秒结束等待且允许重试。

## 测试策略待确认

正式实现前，由产品方先提出关键测试目标、失败场景和边界情况；随后共同从 correctness、failure、security、concurrency、permissions、database consistency、retry/idempotency 分类，并标为 P0/P1/P2。本规范的验收标准只定义结果，不替代该测试评审。

## 实施顺序

1. 确认测试策略和最小真实截图样本集。
2. 实现并验证图片转换、压缩和服务端输入边界。
3. 实现额度的数据库并发控制。
4. 接入 Google Vision，完成确定性结构化和课程匹配。
5. 实现候选模态框。
6. 实现原子批量加课及权限测试。
7. 用真实截图评估课程级 precision、recall 和默认勾选准确率。
8. 按项目顺序运行 `npm test`、`npm run build`、`npm run lint`、`npm run typecheck`。
